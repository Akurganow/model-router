# What omp exposes to an extension and to a headless run

## Discovery

Live runs of omp 18.2.8 during The Hit and Laundering, checked against the omp documentation.

## Solution

- `pi.getAllTools()` returns the task tool's schema and description. The `effort` field appears in `tasks.items.properties` only when `task.enableEffort` is on. The `### task` entry shows whether the user replaced the bundled `task` agent.
- `ctx.models.resolve()` resolves chat models only, so judge models such as TypeSafe's cannot be resolved there.
- In `omp -p`, task spawns run in the background by default, and the run exits before the subagent's answer arrives. A `--config` overlay with `async.enabled: false` makes the parent wait.
- omp installs from a committed `bun.lock` with `--frozen-lockfile --ignore-scripts` and runs a full headless case.

## Project Commandment

Read harness state through its documented extension API, and run headless evals with background tasks off.
